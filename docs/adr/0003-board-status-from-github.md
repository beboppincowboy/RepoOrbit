# Board columns come only from a GitHub status source

The Board shows GitHub issues as cards, and RepoOrbit keeps no task or column state of its own. Each repository chooses a status source: a linked GitHub Project's Status field, or configured `status:todo`, `status:in-progress`, and `status:review` labels. With labels, Backlog means an open issue with no status label and Done means a closed issue. We chose this over deriving columns from open/closed state, assignees, and linked PRs because derived columns cannot represent a team's real workflow. We chose it over a local column store because a local store would drift from GitHub and recreate the separate task model the glossary rules out. Repositories without a status source show their issues under "No status source" and are never placed in a column by inference.

The status source is a repository setting shared by every viewer, so only users with Admin or Maintain permission on that repository may change it. The GitHub App asks for the Projects permission only when someone links a Project. Creating status labels goes through the same review-before-submit flow as other writes. A card move is a GitHub write. It shows as pending until GitHub confirms it, and is rolled back and resynced if the write fails.
